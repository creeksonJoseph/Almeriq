# Documentation source map

This index records the implementation source for each maintained guide. It is not a second specification: code, generated OpenAPI, migration history and the live provider dashboards remain authoritative in their respective areas.

## Source-of-truth rules

1. **API contracts:** use the running FastAPI OpenAPI schema generated by `server/main.py`; router decorators and Pydantic schemas explain the implementation.
2. **Frontend routes and guards:** use `frontend/src/App.jsx` and the referenced guard components.
3. **Business behavior:** use the matching router, service, repository, model and frontend hook/page. A UI label is not proof of backend behavior.
4. **Database schema:** use `server/models/` plus `server/migrations/versions/`; use migrations for deployed schema history.
5. **Build and deployment configuration:** use the checked-in workflow and deployment files for declared configuration only. Render/Vercel dashboards, production secrets, DNS, backups, external provider status and deployed branch settings must be verified in those services.
6. **Verification claims:** cite the exact CI run/commit. A passing CI run does not prove browser E2E, live integrations, production migrations or production database performance.
